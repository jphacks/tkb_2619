## 製品概要
### 背景(製品開発のきっかけ、課題等）
- カラオケでは世代が違うと相手の知っている曲が分からず選曲に時間がかかる
- パーティーでは国籍・言語が違う参加者同士で音楽の好みが分からず、場に合う曲が選べない
- ドライブでは同乗者の好みが分からず、知らない曲ばかりかけても盛り上がらない
- 「お互いの好みが分かれば距離が縮まるはず」なのに、それを手助けするツールがない

### 製品説明（具体的な製品の説明）
Music Bridge は、参加者の「知ってる曲・よく聴く曲」や世代・国籍・好きなジャンルといった属性から、**全員が楽しめる曲**を見つけるためのモバイルファーストWebアプリです。

1. シーン（カラオケ／パーティー／ドライブ）を選択
2. 参加者を選択（モックでは世代・国籍・好きなジャンルが異なるプリセット人物から選択）
3. 「共通曲抽出」「投稿曲」「属性レコメンド」の3つの候補リストを確認
4. Tinder風のスワイプUIで候補曲に0〜3段階評価を投票
5. 候補ランキング（共通度合い）× 投票スコアの加重平均で最終プレイリストを表示

### 特長
#### 1. 共通曲抽出
参加者それぞれの「知ってる曲」リストの重複（タイトル＋アーティスト名の一致）を集計し、知っている人数が多い順に提示。被りのない投稿曲・AIレコメンド曲は並列のリストとして表示する。

#### 2. スワイプ投票
候補曲をカード化し、上下左右のスワイプ（またはボタン操作）で0〜3段階評価を記録。参加者ごとに順番に端末を回して投票できる。

#### 3. 属性レコメンド
世代・国籍・好きなジャンルの3つの軸でフィルタをかけ、参加者の属性に合う曲を提示する簡易レコメンドロジック。

### 解決出来ること
- 選曲にかかる時間を短縮し、「知らない曲で場が冷める」を防ぐ
- 世代・国籍・ジャンルのギャップがある相手とも共通点を見つけやすくなる
- 投票を通じてその場にいる全員の好みを可視化できる

### 今後の展望
- Spotify Web API 連携による実際の再生履歴・プレイリストからの「知ってる曲」自動抽出
- MusicBrainz API 等への差し替えによるパブリック楽曲データの拡充
- 曲の重複判定をジャンル／アーティスト単位の緩い一致に拡張
- 実際の音源再生・Spotifyでのプレイリスト自動生成

### 注力したこと（こだわり等）
* 将来の外部API（Spotify/MusicBrainz）差し替えを見据え、楽曲データ取得層を `lib/music-source/` にインターフェースとして分離
* モックデータのみで3つのコア機能（共通曲抽出・投票集計・属性レコメンド）が完全に動作するよう設計
* スマホでの操作を前提に、スワイプジェスチャー＋ボタン操作の両対応UIを実装

上部の「Open in GitHub Codespaces」バッジをクリックするだけで起動できます。

### ローカル環境で起動する場合
```bash
npm install
npm run dev
```

`http://localhost:3000` を開くとシーン選択画面から始まります。

Spotify連携等で環境変数が必要になった場合は `.env.local` に追加してください（`.gitignore` 済み）。

## 開発技術
### 活用した技術
#### API・データ
* モック楽曲データ（`src/lib/music-source/mock.ts`）
* 将来差し替え予定: Spotify Web API / MusicBrainz API（`src/lib/music-source/spotify.ts`, `musicbrainz.ts` に設計メモを記載）

#### フレームワーク・ライブラリ・モジュール
* Next.js (App Router) / TypeScript
* Tailwind CSS
* framer-motion（スワイプUI）
* zustand（グローバル状態管理）

#### デバイス
* スマートフォン（モバイルファーストUI、タッチ・スワイプ操作を想定）

### 独自技術
#### ハッカソンで開発した独自機能・技術
* 共通曲抽出アルゴリズム: `src/lib/logic/common-songs.ts`
* スワイプ投票 → 0〜3段階評価の集計ロジック: `src/lib/logic/voting.ts`
* 属性ベースレコメンド: `src/lib/logic/recommend.ts`
* 候補ランキング × 投票スコアの加重平均で最終順位を決めるロジック: `src/lib/logic/ranking.ts`
