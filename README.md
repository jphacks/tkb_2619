# [ミューコネ（MusiConnect）](https://jphacks.github.io/tkb_2619/)

## 製品概要
### 背景
世代・国籍・音楽の好みが違う人とカラオケ・パーティー・ドライブに行くと、相手がどんな音楽を好きなのか分からず、選曲に困ることがよくあります。

#### 具体例
| シーン | ギャップ | 起きていること |
| --- | --- | --- |
| 上司とのカラオケ | 世代（上司と部下） | 上司の好きな曲が分からず、歌う曲を選びにくい |
| 留学先でのホームパーティー | 国籍（他国からの留学生） | 場が盛り上がる邦楽・洋楽を流したいが、文化や言語の違いから選曲が難しい |
| サークルでの初ドライブ | 音楽ジャンル | 同乗者の好みが分からず、無難な曲ばかり流してしまう |

共通する課題は、「相手の曲の好みが分からず選曲できない」ことと、「好みが合えば距離が縮まるはずなのに、無難な曲しか流せない」ことです。
この課題を解決するために、みんなに共通する好きな曲を見つけ、人と人をつなぐアプリ「ミューコネ（MusiConnect）」を作りました。

### 製品説明
**共通の好きな曲が、心をつなぐ。** ミューコネは、みんなが知っている曲・聴きたい曲を投票で選ぶ選曲アプリです。

1. **ルームを作成**: 幹事が、集まる人たちの属性（性別・ジャンル・国籍・年代は複数選択、その他は自由入力）をAIレコメンドの条件として設定し、招待URLを発行
2. **招待URLから参加**: URLを受け取った人は、「Spotifyで登録・連携」か「アカウントを持っていない」のどちらかを選んで参加
3. **曲の候補を集める**
   - Spotifyデータ: 過去1ヶ月によく聴いた曲を取り込む
   - 手動: 検索やおすすめから、Spotifyには入っていないけれど知っている曲を追加
   - AIレコメンド: 条件と参加者の好みに近い曲を提案（OFFにすると、手動で追加した曲とSpotifyデータだけが候補になる）
4. **スワイプで投票**: 多くの人と被った曲から順に表示され、上=Best(3点) / 右=Better(2点) / 下=So-so(1点) / 左=Nope(0点) で評価。スワイプすると次の曲が表示される
5. **みんなのランキング**: 投票が入るたびに、リアルタイムで順位が更新される

### 特長
#### 1. 「被る曲」の抽出
Spotifyで過去1ヶ月によく聴いた曲を参加者ごとに取り込み、参加者の間で重複している曲を見つけます。被った人数とよく聴いた度合いをもとに順位を付け、上位の曲を投票に回します。

#### 2. スワイプ投票とリアルタイムランキング
マッチングアプリのように上下左右にスワイプして、0〜3点で評価します。投票結果から最終順位を決め、全員の画面にリアルタイムで反映します。

#### 3. 条件付きAIレコメンド
性別・ジャンル・国籍・年代・自由入力（例:「みんなで歌える、明るい曲がいい」）の条件と、Spotifyデータや手動で追加された曲の傾向から、候補を提案します。

### 解決出来ること
- 選曲にかかる時間を短縮し、知らない曲ばかりが流れる状況を防ぐ
- 世代・国籍・ジャンルのギャップがある相手とも、お互い知らなかった共通の好きな曲が見つかり、仲を深められる

### 今後の展望
- 「その他」の自由入力をLLMで解釈する（APIキーを隠すため、Supabase Edge Function 経由で呼び出す）
- 世代別・国別の実際のチャートデータで、AIレコメンドの母集団を拡充する（現在はキュレーション済みのカタログ）
- 曲名の表記ゆれ（Idol / アイドル）の同一視や、ジャンル・アーティスト単位のゆるい一致
- Spotifyのプレイリスト自動生成、ルームごとの参加トークンによるアクセス制御

### 注力したこと（こだわり等）
* 企画段階で決めた機能の流れ（候補出し3種 → 投票 → レコメンド → 曲を流す）を、1つのルーム体験にまとめた
* サーバーなし（GitHub Pages）で、Spotifyログイン（PKCE）・MusicBrainz・Supabase Realtime をブラウザから直接使う構成にした
* 外部データの取得部分（`src/lib/music-source/`）とルームの保存先（`src/lib/room/`）を分離し、Supabase未設定でも同じブラウザ内のデモモードで全機能が動くようにした

## セットアップ手順

### GitHub Codespaces（インストール不要・一番簡単）
[こちら](https://codespaces.new/jphacks/tkb_2619?quickstart=1)をクリックするだけで、GitHub Codespaces上で起動できます。

### ローカル環境で起動する場合
```bash
npm install
npm run dev
```

`http://127.0.0.1:3000` を開いてください（Spotifyログインは `localhost` では使えないため）。

### Supabase（招待URLで複数の端末から共有する）
未設定の場合は「デモモード」になり、ルームは同じブラウザ内（タブ間）だけで共有されます。

1. [Supabase](https://supabase.com/) でプロジェクトを作成
2. SQL Editor に [`supabase/schema.sql`](supabase/schema.sql) を貼り付けて実行
3. Project Settings → API の **Project URL** と **anon public キー** を `.env.local` に設定（`.env.example` 参照）。公開サイトに反映するには `src/lib/config.ts` の既定値かGitHub Actionsの環境変数に設定する
4. **service_role キーは秘密鍵なので、絶対にコードや `.env` に置かないこと**

### Spotify（[ダッシュボード](https://developer.spotify.com/dashboard)）
- Redirect URIs に `https://jphacks.github.io/tkb_2619/callback` と `http://127.0.0.1:3000/callback` を登録
- 開発モードのアプリは **User Management に登録したアカウントだけ** ログインできる
- Client ID はPKCE方式では公開されて問題ない値のため、コードに既定値として入っている。**Client Secret はこのアプリでは使わない**
- Codespaces のURLは登録していないため、CodespacesではSpotifyログインは使えない

## 開発技術
### 活用した技術
#### API・データ
* Spotify Web API: 過去1ヶ月のトップトラック（`time_range=short_term`）。再生回数は取得できないため、順位から求めた重みで代用
* MusicBrainz API / Cover Art Archive: 曲検索、アーティストの国・ジャンル、ジャケット画像
* Supabase（Postgres + Realtime）: ルーム・参加者・候補・投票の共有とリアルタイム更新
* キュレーション済み楽曲カタログ（`src/lib/music-source/catalog.ts`）: AIレコメンドの母集団

#### フレームワーク・ライブラリ・モジュール
* Next.js (App Router, 静的書き出し) / TypeScript / Tailwind CSS
* framer-motion（スワイプUI）、lucide-react（アイコン）、@supabase/supabase-js

#### デバイス
* スマートフォン（モバイルファーストUI、タッチ・スワイプ操作を想定）

### 独自技術
#### ハッカソンで開発した独自機能・技術
* 候補ランキング（被った人数・よく聴く度合い・AI・ニッチ度）と最終ランキング: [`src/lib/logic/ranking.ts`](src/lib/logic/ranking.ts)
* 条件付きAIレコメンド・あなたへのおすすめ: [`src/lib/logic/recommend.ts`](src/lib/logic/recommend.ts)
* ルームの保存先の抽象化（Supabase / ブラウザ内デモ）: [`src/lib/room/`](src/lib/room/)
* スワイプ投票カード: [`src/components/VoteCard.tsx`](src/components/VoteCard.tsx)
